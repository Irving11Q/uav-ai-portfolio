# 毕设方案：基于 Langchain 的企业级电商 RAG 知识库问答系统

> 目标：用 Langchain 搭建一个浏览器可用的「电商商品知识库问答系统」。用户登录后能向知识库提问，系统检索商品知识并**引用原文片段**作答；管理员集中维护知识库；支持多用户、多会话、历史可找回。

---

## 0. 一句话定位
用户（买家/客服）在浏览器里问商品问题 → 系统从商品知识库检索相关片段 → 带着引用生成答案 → 前端同时展示「回答」和「引用了哪几段原文」。管理员在后台上传/维护商品资料。

## 3. 技术选型（我的建议）

| 层 | 技术 | 理由 |
|---|---|---|
| RAG 框架 | **Langchain**（强制）+ LangGraph 编排 | 你的硬性要求；LangGraph 便于做多步检索/重写 |
| 后端 | FastAPI（异步） | 天然契合 Langchain、自动 OpenAPI 文档、答辩演示友好 |
| 前端 | Vue3 + Element Plus | 你已有 Vue3 经验，组件全、上手快 |
| 关系库 | **SQLite（本机一键零配置）** | 你选「本机一键运行」，SQLite 免装服务；企业级部署可换 PostgreSQL |
| 向量库 | **Chroma（进程内持久化，零服务）** | 你选定；免独立服务，契合本机一键 |
| Embedding | **bge-small-zh-v1.5（本地）** | 免费、中文效果好、你本机已缓存，无 API 费用 |
| LLM | **通义千问 API**（DashScope，OpenAI 兼容，可插拔） | 你选定；已持 DeepSeek/GLM 密钥，可后台切换 |
| 鉴权 | JWT + bcrypt | 无状态、易扩展 |
| 缓存/限流 | Redis（企业级增强；先做内存版） | 语义缓存 + 限流 |
| 文档解析 | Langchain Loaders + PyMuPDF + python-docx + pandas | 支持 PDF/Word/TXT/MD/Excel/CSV |

> **部署说明（你选「本机一键运行」）**：后端 `python run.py` 直接起，前端 `npm run dev`（或 build 后由后端托管）。SQLite + 进程内 Chroma 均免服务、免安装，一条命令跑通，答辩演示最稳；后续上云换 PostgreSQL 仅改配置不改动业务代码。

### 3.1 关键设计：用户层 / 索引层显式分层（Markdown 只做中间表示）

系统的「用户视角」与「机器视角」是分离的，这是本方案的一个核心设计点：

```
用户层（人看的）      上传 .docx ──────────► 知识库列表 / 下载原件（仍是 .docx）
                          │                        ▲
                          │ 原样保存到 uploads/    │ 原件下载接口
                          ▼                        │
索引层（机器读的）     to_markdown 归一化 ──► Markdown ──► 结构感知切块 ──► 向量库
```

- **用户永远看到自己熟悉的格式**：上传什么格式，列表里就是什么格式，下载回去也还是什么格式（`.docx` 仍是 `.docx`）；原始文件原样保存，索引过程不改动它。
- **Markdown 只是索引层的中间表示（IR）**：Word 的标题层级、表格结构在纯文本化时会丢失，导致分块只能按字数硬切（表格被拦腰切断、续块没有表头）。转成 Markdown 后，切块器就能「按 `##` 标题切、表格整体成块」。
- **中间表示不对外暴露**：引用片段与模型回答在前端渲染成正常排版（表格有边框、标题有层级），用户看不到 `**加粗**`、`| 表格 |` 这类源码。

> 答辩可讲点：这是典型的「关注点分离」——把对人的呈现格式和对机器的索引格式解耦，既保证用户无感（不用把 Word 转成 md 再上传），又让检索质量拿到结构化收益。

## 4. 功能设计要点

### 4.1 知识库管理（仅 admin）
- 上传多格式文档 → 自动解析 → 智能分块 → 向量化 → 入库，前端显示处理进度。
- 列表查看文档与分块数；支持删除单个文档（连带清理向量）、重新索引、**下载原件**、查看命中统计。
- 商品资料常见结构：标题/规格/价格/卖点/FAQ → 用「结构感知分块」提升检索精度（见 4.5）。

### 4.2 问答 + 引用（核心）
- 提问 → 检索 top-k 相关分块（带相似度分数）→ 拼入带引用提示词 → LLM 生成。
- 回答中标注 `[1][2]` 引用，前端展示「引用来源」卡片（文档名 + 原文片段 + 相似度）。
- 支持多轮对话：历史消息压缩后带入，控制 token 成本。
- 流式输出（SSE），边生成边显示，体验接近商用。

### 4.3 多用户 / 多会话 / 持久化
- 每个用户有独立会话列表，可新建/重命名/删除会话。
- 所有消息落库，任意时间登录都能拉回历史；支持导出对话。

### 4.4 权限
- 首次启动自动建 `admin / 123456`；普通用户仅问答路由，管理端路由加 admin 校验中间件。

## 5. 企业级性能优化（答辩加分项）
1. **混合检索**：向量检索 + BM25 关键词融合，补齐纯向量在「商品型号/规格」上的短板。
2. **重排 Rerank**：cross-encoder 对初召回 top-N 重排，提升精度。
3. **语义缓存**：相似问题复用答案，降 LLM 调用与延迟。
4. **向量索引调优**：HNSW 参数 + 相似度阈值过滤低质片段。
5. **异步 + 后台任务**：文档索引走后台任务并回报进度，不阻塞接口。
6. **分块策略**：结构感知分块（已落地）——Markdown 按 `#`/`##`/`###` 切节、标题保留在块内；**表格整体成块，超长拆分时每块复制表头**；短于 100 字的碎块自动合并；非结构化文本退回中文递归字符切分（`\n\n`→`\n`→`。！？`→`；，、`，带 80 字重叠）。
7. **多轮上下文压缩**：LLM 摘要历史，避免超长上下文与费用膨胀。
8. **限流与可观测**：按用户限流；结构化日志 + 基础指标；检索为空时走通用回答并提示。

## 11. 实施后修订（as-built 与初稿的差异）

初稿是动手前的规划，实施中部分选型做了调整，此处如实记录，便于答辩时解释「为什么变了」：

| 项 | 初稿设想 | 实际落地 | 变更原因 |
|---|---|---|---|
| Embedding | 本地 bge-small-zh-v1.5 | **DashScope `text-embedding-v3`**（保留 `EMBEDDING_BACKEND=local` 开关可切回本地） | 与 LLM 同厂商同协议更省心；本地模型首次加载慢，一键交付体验差；批量上限 10 条已在代码中处理 |
| 重排 | cross-encoder 本地模型 | **DashScope `gte-rerank`** | 免本地模型下载，部署体积大幅下降 |
| 编排 | 初稿提过 LangGraph | **LangChain 0.3 模块化管线**（自实现 RRF + 编排） | 本场景是线性管线，图编排属过度设计；自实现融合逻辑更可控、可解释 |
| 缓存/限流 | 初稿提过 Redis | **SQLite + 进程内滑动窗口** | 交付形态是「单机一键运行」，引入 Redis 等于多一个必须安装的服务 |
| PDF 解析 | PyMuPDF | **pypdf + pypdfium2** | 许可与体积更友好 |
| Excel | pandas | **openpyxl** | 只为读写表格，pandas 过重 |
| 传输 | 双进程（5173 + 8000） | **单端口**（FastAPI 托管前端产物） | 交付给他人时不该要求对方装 Node |
| admin 口令 | `admin / 123456` | 首次启动播种，**使用后应改密** | 默认口令是一次性引导口令，不应长期有效 |

**未变的决策**：LangChain 作为 RAG 框架、SSE 未采用（改为完整响应 + 前端渲染）、
SQLite、Chroma、Vue3 + Element Plus 均按初稿执行。

### 11.1 阶段6 实测要点（可写进答辩）

- **语义缓存**：同一问题二次提问 **8.84 s → 0.95 s（约 9.3×）**；命中不调用大模型。
- **混合检索 + 重排**：向量 ∥ BM25 → RRF(k=60) → gte-rerank 精排 → top5。
- **权限隔离**：普通用户访问 `/api/dashboard`、`/api/audit-logs`、`/api/settings`、
  `/api/documents` 全部返回 **403**。
- **稳定性**：每用户 20 次/分钟滑动窗口限流（超限 429）；大模型并发信号量 4。
- **导出**：Markdown 与 PDF 均可导出；PDF 在无微软雅黑环境自动降级为 CID 中文字体，实测可正常打开。
- **可观测**：仪表盘 7 个指标卡（文档数/分块数/用户/问答量/缓存命中率/平均响应/满意度）+ 趋势图、热问榜、审计分布、审计日志可追到「谁在何时问了什么」、bad case 可标记处置。
- **工程规模**：后端 4628 行/35 文件，前端 3426 行/16 文件，43 个 HTTP 接口（39 个 REST 路径），10 个页面。
